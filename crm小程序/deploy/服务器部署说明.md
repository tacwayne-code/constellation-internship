# CRM 服务器部署说明

发布包同时包含构建后的 H5 页面与 Python API。服务器需要 Python 3、systemd、Nginx，不需要 Node.js。

## 上传与解压

```bash
scp crm-miniapp-web-server-20260721-handover-final.zip sameng@服务器IP:/tmp/
ssh sameng@服务器IP
cd /tmp
unzip crm-miniapp-web-server-20260721-handover-final.zip -d crm-release
cd crm-release
cd crm-miniapp-web
```

## 配置并发布

默认目录为 `/home/sameng/apps/crm-v01`，服务监听 `127.0.0.1:8123`。服务器用户或目录不同时，先修改 `deploy/crm-v01.service`。

```bash
mkdir -p /home/sameng/apps/crm-v01/shared
if [ ! -f /home/sameng/apps/crm-v01/shared/crm.env ]; then
  cp deploy/crm.env.example /home/sameng/apps/crm-v01/shared/crm.env
  chmod 600 /home/sameng/apps/crm-v01/shared/crm.env
fi
chmod +x deploy/install-release.sh
./deploy/install-release.sh
```

当前测试服务器已经接通 Odoo 测试版与高德实时 API。接手现有服务器时不要覆盖 `shared` 内的私有环境文件，直接运行发布脚本即可沿用现有 Key 和测试账套配置。只有新建服务器或明确变更配置时，才编辑 `crm.env`。

新云服务器必须由公司在高德开放平台申请“Web服务”Key，并填写 `AMAP_WEB_SERVICE_KEY`。Odoo 未接通时保持 `CRM_ERP_MODE=MOCK`；接通测试账套后改为 `ODOO_TEST` 并填写 Odoo 配置。公司内部测试账套信息见根目录 `测试环境敏感配置.md`。

脚本会创建时间戳版本目录、保留 `shared` 内的数据与密钥、切换 `current`、重启服务并检查 `/api/health`。

## 域名与 HTTPS

复制 `deploy/nginx-crm.conf.example` 到 Nginx 配置目录，将 `crm.example.com` 改为真实域名，检查并重载 Nginx。微信小程序 `web-view` 必须使用已备案的 HTTPS 域名。

## 检查

```bash
systemctl status crm-v01.service
curl http://127.0.0.1:8123/api/health
journalctl -u crm-v01.service -n 100 --no-pager
```

当前测试环境健康接口应返回 `erpMode: ODOO_TEST` 和 `routeMode: AMAP_LIVE`。如果发布后变成 `MOCK`，说明服务器私有环境文件没有被服务加载，应先恢复原配置，不需要修改前端代码。

当前代码已包含服务器端行程报销数据、销售经理审批和权限校验，并有自动化测试覆盖。正式使用前仍需在公司微信、HTTPS 域名和真实服务器环境完成端到端验收；当前审批只到销售经理，不包含财务付款或财务系统对接。
