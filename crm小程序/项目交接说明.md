## 3. 当前功能状态

已经在代码和自动化测试中实现：

- 客户、联系人、拜访、销售意向、实际销售及操作记录。
- 拜访转意向、意向推进和转实际销售、实际销售确认。
- 共享服务器 JSON 持久化、统一业务编号、关联校验和操作人记录。
- Odoo 测试版已接通：当前测试账套为 `inspiri_erp_test`，支持商品只读搜索、报价草稿提交、幂等查询和失败重试。
- 高德 Web 服务 API 已接通：当前测试服务器健康接口返回 `routeMode=AMAP_LIVE`，支持驾车路线、地理编码和逆地理编码。
- 行程报销提交、员工只看本人报销、经理查看待办、通过/驳回和归档。
- 微信登录、手机号验证、员工申请、经理审核和移除员工。
- 员工文件为空时，第一个完成手机号验证和实名注册的账号自动成为销售经理；后续账号等待经理审核。

需要在公司真实环境继续完成或验收：

- 将 `wechat-miniapp/project.config.json` 的 `touristappid` 换成公司小程序 AppID。
- 将 `wechat-miniapp/config.js` 的示例域名换成已备案 HTTPS 域名，并在微信公众平台配置 `request 合法域名` 和 `业务域名`。
- 使用公司微信小程序、真实 HTTPS 域名验证完整登录、手机号授权和 `web-view` 流程。
- 当前测试服务器已经配置高德 Web 服务 Key，仅用于证明路线功能已接通。正式迁移到新云服务器时，接手人员应使用公司主体在高德开放平台申请新的“Web服务”Key，写入服务器私有环境文件的 `AMAP_WEB_SERVICE_KEY`，不得写入前端或小程序代码。
- 当前连接的是 Odoo 测试账套，不需要重做测试对接；将来切换正式库时再使用公司批准的最小权限集成账号完成正式库验收。当前设计只创建报价草稿，不确认销售订单，不直接修改库存、采购或生产。
- 配置 HTTPS 证书。包内 Nginx 文件是 HTTP 反向代理示例，不包含公司证书配置。
- 决定 JSON 文件存储是否满足正式规模。当前实现适合单机、单服务进程；若要多实例或提高可靠性，应规划数据库迁移。

生产服务器的关键持久化目录为：


## 5. 身份与权限注意事项

- 生产环境应设置 `CRM_AUTH_MODE=WECHAT`；`DEMO` 只用于浏览器演示和测试。
- 员工数据为空时，首个注册账号会自动成为销售经理。首次开放生产入口前，应由公司指定经理先完成注册，避免错误账号取得经理权限。
- 默认最多 1 名销售经理、10 名销售人员；代码可通过 `CRM_MAX_MANAGERS`、`CRM_MAX_SALES` 调整。
- 系统禁止移除当前登录经理，并保护最后一名有效经理。
- 手机号是员工唯一标识，微信 `openid` 是登录绑定凭证。

当前部署示例写死了以下默认值，环境不同时必须先修改：

- Linux 用户/组：`sameng`
- 应用目录：`/home/sameng/apps/crm-v01`
