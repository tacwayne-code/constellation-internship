# MVP 0.1 交付说明

## 软件闭环

业务创建 → 原子预留源/目标 → 单堆垛机队列 → 移动到源 → 取货 → 收叉 → 移动到目标 → 放货 → 收叉 → 完成任务、更新库存并生成回执。

库存以实际位置为准：取货后载具位于 FORK，放货后位于目标；出库站台提走后标记 DISPATCHED。任务完成和业务系统确认分别记录。相同 request_id 重试返回原结果，不同载荷复用同一个 ID 会被拒绝。排队任务可取消，执行中任务不能用取消绕过物理恢复。

SQLite 事务保证本地快照一致性。它是单进程 MVP 存储，不是已完成的生产数据库设计；后续迁移 PostgreSQL 时需保留预留互斥、任务幂等与事务回执语义。

## CAD 处理

来源：结构/样板间总装.SLDASM，32 个装配体、315 个零件。通过本机 SolidWorks 只读打开并提取面三角网格，生成 assets/structure/sample-room.glb。原始资料未改写。

提取结果：2704 个可用实例、315 个唯一网格；浏览器版本省略名称匹配紧固件、轴承、链条等细节后保留 1382 个实例、190 个唯一网格。缺网格构件：LG2-200000-1/LG2-210000-1/LG-214000BJ-1/100X100铝地轨-1。详细结果见 assets/structure/mesh-report.json。

真实预览是静态装配；运行总览使用左右两侧、6 列、4 层共 48 库位的参数化模型。此演示拓扑、坐标、速度尚未完成现场标定，不能从演示编号推导 PLC 地址。总装包围盒约 15.94 × 3.46 × 3.55 m，是 CAD 近似包围盒，不是确认后的有效行程。

重建脚本：scripts/extract-cad-mesh.ps1 → scripts/build_cad_glb.py → scripts/index_structure.py。提取脚本依赖本机 SolidWorks 2022 安装路径；其他机器须调整路径并具备 SolidWorks。启动应用不需要安装 SolidWorks。

## 已验证

17 项自动化测试覆盖：完整业务闭环、幂等和冲突、源/目标预留互斥、并发抢位、暂停/单步、带货故障恢复、不同阶段重启恢复、队列取消、模拟回执重复确认、出库站台占用、串行调度、API 校验和跨来源写入拒绝、20 次混合移库库存守恒。

在内置浏览器实际操作 QA-MVP-001 入库 L-03-02、移库 R-04-04、出库 OUT 并确认提走，完成 3 个任务，最终回到 8 个初始在库载具。验证了故障注入/清除/恢复及模拟回执。桌面和 390px 移动端检查通过，页面无横向溢出，检查时浏览器控制台无错误/警告。前端生产构建通过。

尚未执行：真实 PLC 联调、断网网络协议测试、真实 Odoo 回写、长时稳定性/吞吐量、机械碰撞和现场安全验收。测试结果不代表这些项目通过。

## 下一阶段顺序

1. 从总装确认巷道、实际层列、左右/深位、站台和运动组件；建立 CAD 节点—业务库位—PLC 坐标映射并校准。
2. 确认 DB2 握手、任务号回绕、字节序、故障位、完成确认与断线恢复。现有表中的功能号可参考，尚未实现发送。
3. 在独立适配器中实现实际 PLC 驱动，先进行协议仿真及只读联调，再接设备任务闭环；运动与安全互锁仍由 PLC 负责。
4. 按实际 Odoo 版本实现连接器，冻结库存事实来源、单据与库位映射、重复回执/补偿规则，保留 outbox 接口。
