# 交付塔 V1 · 项目与现场管理

保留已确认的浅色、大字、紧凑界面，实现独立的项目管理应用。启动后访问 http://127.0.0.1:8782 。原概念演示继续使用 8781，灯塔继续使用 8780。

## 首次使用

1. 运行项目根目录的 `启动交付塔.ps1`。首次会安装锁定的依赖并构建前端。
2. 在浏览器创建管理员，账号为3–64位字母、数字、点、短横线或下划线；密码至少10个字符。
3. 创建实际项目，填写负责人、位置、交期，调整交付节点。
4. 在“账号与设置”创建协作账号，再将账号加入具体项目。
5. 建立任务、问题、物资和人员记录。资料先建立记录，再上传文件。

正式数据库初始为空。不会把概念版示例、浏览器 localStorage 或验证环境里的数据自动导入正式项目。

## 已实现

| 模块 | 行为 |
|---|---|
| 项目 | 多项目切换，创建、编辑、交付节点、归档与恢复 |
| 任务 | 新建、编辑、负责人、关联账号、优先级、截止时间、完成与重开、搜索筛选、我的待办 |
| 问题 | 风险等级、负责人、计划解决日期、下一步、跟进记录、已解决状态；首页统计未解决问题 |
| 资料 | 类型、来源、维护人、真实上传下载、历史文件、图片/PDF预览、版本确认与作废 |
| 采购 | 现场采购跟踪记录，供应商、数量、交期、状态、跟进；明确关联Odoo采购单，只读刷新 |
| 现场库存 | 物资目录、规格、位置、单位、收料、领用、退料、盘盈、盘亏、流水与结存 |
| 外包人员 | 姓名、班组、现场岗位、任务说明、进退场；与系统登录账号独立 |
| 账号权限 | 管理员、项目负责人、协作成员、只读成员；密码修改、停用账号、会话失效 |
| 操作记录 | 项目动态、修改前后、操作人和时间；首页显示最近记录，动态页显示最近200条，数据库保留全部 |
| 备份 | 每日自动备份、管理员下载完整备份、恢复到新目录，包含数据库和文件历史 |

外部通知推送、MES报工、PLM管理与BOM写入不在本产品内。Odoo当前接入的是既有测试账套，已实际验证采购读取字段；没有将其误称为生产账套。仅连接采购单级信息，未推断物料与项目的自动关系。

## 权限边界

系统管理员可以访问所有项目、创建项目和账号、停用账号以及导出完整备份。

项目负责人可以管理本项目节点、成员权限、资料确认、库存盘点与采购单关联。普通协作成员可以维护现场记录、上传待确认文件、处理任务和登记出入库；不能确认图纸或进行盘点调整。只读成员只能查询和下载所属项目资料。

新账号的跨项目分配由系统管理员完成；项目负责人可调整已加入成员的权限。停用账号立即撤销其所有会话。移除项目成员后，其会话即使仍有效也不能继续访问该项目。权限校验在服务端执行。

## 数据规则

- 所有正式业务数据保存在根目录 `.delivery/delivery.sqlite3`，已加入忽略规则。不要公开提交此文件或其备份。
- SQLite 使用 WAL、外键和事务。附件作为BLOB保存在同一数据库，文件和记录可以一致备份。
- 库存数量支持最多3位小数，使用 Decimal 计算，不直接覆盖结存。首次库存通过收料或负责人盘点登记。已有流水的物资不可修改单位。
- 出入库带唯一操作编号，重复提交同一操作不会重复记账。并发领用不会产生负库存。
- 编辑记录校验版本号；多人修改同一记录时，后保存者收到冲突提示，不能静默覆盖。
- 上传新版保留全部历史，并自动回到“待确认”。仅项目负责人或管理员能确认“可使用”。支持 PDF、PNG、JPG、XLSX、DOCX、DWG、DXF、CSV、TXT，单文件20MB。Office/CAD等文件下载后使用相应软件打开。
- Odoo采购按明确单号或来源查询，由负责人确认关联。上游不可用时保留旧记录及原读取时间，明确显示失败；不会自动显示示例。
- 显示日期使用北京时间；Odoo的UTC计划时间先转换，再确定日期。
- 密码使用带独立随机盐的 scrypt，登录会话使用随机令牌且数据库只存令牌哈希。Cookie为HttpOnly和SameSite=Strict，写操作另有CSRF校验。密码或登录令牌不进入前端存储。
- 字号偏好可以保存在浏览器；业务数据不能靠浏览器 localStorage 充当数据库。

## 备份与恢复

服务运行时每天在 `.delivery/backups` 生成一份备份，下载完整备份入口位于“账号与设置”。备份包含人员与附件，应保管在受控位置。当前版本保留每日备份，不自动清理；定期复制到另一块磁盘或异机，避免本机故障同时影响原件和副本。

手动备份（目标文件必须不存在）：

```powershell
.\.venv\Scripts\python.exe -m delivery.backup backup .delivery D:\Backups\delivery-20260909.sqlite3
```

恢复只能写入新的空目录，避免覆盖正在使用的数据库：

```powershell
.\.venv\Scripts\python.exe -m delivery.backup restore D:\Backups\delivery-20260909.sqlite3 D:\Delivery-Recovered
$env:DELIVERY_DATA_DIR = 'D:\Delivery-Recovered'
.\.venv\Scripts\python.exe -m delivery.run
```

恢复前停止原交付塔进程，检查恢复结果后再决定是否切换。恢复会撤销备份中的所有登录会话，需要重新登录。程序校验数据库完整性、结构版本及外键关联。

## 运行与部署

后端 Python / FastAPI，前端 React / Vite；沿用工作区已锁定的 Python 依赖和独立前端锁文件。本轮没有新增第三方托管或公开网站。

默认仅本机监听。前端构建后由后端同源提供，不需要单独启动Vite开发服务。一个服务进程承担日常运行，不开多个采集器或后台同步任务。Odoo直接复用现有只读传输模块和配置；无业务写回路由。

| 环境变量 | 默认 / 用途 |
|---|---|
| DELIVERY_DATA_DIR | 根目录 `.delivery`，正式数据位置 |
| DELIVERY_PORT | 8782 |
| DELIVERY_HOST | 127.0.0.1 |
| DELIVERY_ALLOWED_HOSTS | 非本机开放时指定合法主机名，逗号分隔 |
| DELIVERY_SECURE_COOKIE | HTTPS部署时必须为1 |
| DELIVERY_PROXY_IPS | 可信反向代理的明确IP；默认不信任代理头，拒绝通配符 |

局域网多人上线时，应先在本机初始化管理员，再配置HTTPS反向代理、主机名、安全Cookie、可信代理IP和备份位置。此次已完成本机版本与隔离验证，没有把尚未执行的局域网部署或真实项目验收算作完成。

## Odoo 抓取模块

发布包包含 `lighthouse/odoo.py` 只读传输、`delivery/odoo_fetch.py` 采购抓取和 `delivery/integration.py` 项目关联接口，无需从其他项目复制代码。

1. 将根目录 `.env.example` 复制为 `.env`，在本机填写 `ODOO_URL`、`ODOO_DB`、`ODOO_USER`、`ODOO_PASSWORD`。建议使用具备采购读取权限的专用账号。
2. 安装依赖后运行 `.\.venv\Scripts\python.exe -m delivery.odoo_fetch`。检查只读取最多一张采购单，只输出成功状态与条数，不输出订单内容或连接凭据。
3. 启动交付塔，在项目“采购”页搜索采购单号或来源，确认关联后点击刷新。每批读取最多50张已关联采购单；查询结果超出50条会提示缩小范围。

抓取包括单号、供应商、来源、采购状态、计划日期和上游修改时间。由项目负责人明确关联，当前采用手动刷新；不自动导入全部采购单、不将采购状态当作现场收料。网络或权限失败保留已有记录与读取时间；部分单据不可读时显示部分不可用。账号、`.env`、本地数据库、备份和附件不会随源码提交 GitHub。新机器必须单独配置连接。
