# 交付塔 · 前端概念演示

面向现场项目交付的大字、紧凑工作台。所有项目、人员、采购和资料均为示例；只有前端，没有后台、登录、真实附件或 Odoo 连接。演示修改使用当前浏览器的 localStorage 保存，侧栏“重置演示”可恢复初始内容。

启动：运行上一级的 `启动交付塔演示.ps1`，访问 http://127.0.0.1:8781 。需要 Node.js 和 npm；首次自动安装锁定依赖。也可以在本目录执行 `npm ci`、`npm run dev`。`npm run build` 生成静态文件。

独立子目录和端口，不影响灯塔。使用 React、Vite、Lucide 图标。中文字体为随包附带的 Noto Sans SC，许可证见 public/fonts/OFL.txt；字体来源为 Google Fonts 的 notosanssc 项目。

## 演示路径

- 项目概览：交付节点、今日任务、风险、动态与常用资料。
- 任务与问题：新建、搜索、筛选、查看详情、完成和重新打开；“我的待办”仅显示林远负责的任务。
- 图纸资料：按类型筛选，查看版本、来源、更新时间与确认状态；预览是明确标记的示意，不含真实图纸。
- 采购跟踪：按状态筛选、搜索、保存并再次查看跟进记录。
- 现场库存：收料、领用、退料、结存和出入库记录；领用不能超过结存。
- 外包人员：按班组筛选、搜索、进退场登记，概览人数同步更新。
- 大字开关：关键正文从 18px 提升到 20px。

## 设计与核验

设计参考：design/concept.png，由内置 Image Gen 生成，提示词见 design/prompt.txt。这是一版待用户评审的方向，尚未获得用户设计验收。

设计系统：白色主背景、浅灰蓝侧栏、深色中文无衬线字体、青绿 #087f70 主色；红色高风险和橙色待协调；主标题 32px、区块标题 22px、任务和正文 18px、辅助文字 13–17px；桌面主要间隔 14–20px、任务行约 55px，边框 1px、圆角 5–6px。

已通过构建。使用 Codex 内置浏览器检查了 1536×1024、1366×768、390×844 三种尺寸；没有框架错误画面、空白页或相关控制台错误。使用浏览器截图，并通过 view_image 查看概念图与最终桌面、手机截图，逐项检查以下内容：

1. 左侧导航、标题与按钮层级。
2. 四项摘要、五个交付节点的顺序和对齐。
3. 任务表与右侧协调区的并列结构。
4. 白色背景、浅色侧栏、青绿主色、橙红风险色。
5. 中文字体、任务字号、行高与块间距。
6. 动态、常用资料以及窄屏下的布局延续。

修正了中文字体回退、正文偏小、移动端节点横向溢出和任务表横向滚动问题。桌面保留概念结构，手机任务改为逐条显示；其他较宽表格可局部横向滚动。

相对初始图的有意调整：加入大字开关、重置入口及示例说明；我的待办数按实际负责人计算为 2；规范联调节点名称；图标使用一致的线性图标；正文放大后风险区域自然增高，底部动态和资料表改为更简单的行列表。以上属于为用户明确的大字、紧凑和可演示要求做的实现调整，不是像素级复刻承诺。

交互验证：完成任务使待办 8→7；新建任务后搜索可见；收料 6 根使横梁 48→54，刷新保留并生成记录；人员离场 12→11；资料预览显示待确认与版本；采购跟进保存后重新打开可见；超量领用被拦截；大字模式任务和风险正文实际为 20px。验证后恢复初始演示。

未验证或未实现：真实数据、多人协作、权限、真实附件预览、生产部署与其他浏览器兼容性。本轮只用于概念与交互评审。
