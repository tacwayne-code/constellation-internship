# 灯塔 · 运营副屏

灯塔以有限信息和无声颜色提示传达 Odoo 业务变化。保留早期看板的暗色背景、色块墙、订单行和远距离阅读布局。

灯塔保持独立的只读副屏定位。交付塔是同工作区内独立运行的现场项目管理应用；MES、PLM、CRM/ASS 均不在整合范围。灯塔和交付塔均不向 Odoo 写回业务数据。

## 交付塔 V1

运行 `启动交付塔.ps1`，访问 http://127.0.0.1:8782 ，首次创建管理员后建立实际项目。包含项目、任务与问题、资料附件版本、采购跟进、现场库存、人员、权限和备份。详见 [交付塔使用与维护说明](delivery-tower/README.md)。原概念演示仍在 http://127.0.0.1:8781 ，灯塔继续使用8780。

## 已实现

- 四个入口：采购异常、库存通知、紧急采购、订单交付。
- 采购与库存共用快照；旧生产订单与交付流程屏合为订单交付。
- 独立地址、地址恢复、专注副屏、全屏、订单分页。
- 原展示样式与逻辑择优迁入本项目，不依赖旧服务；旧项目未修改。
- FastAPI + httpx 统一只读读取。模型和方法双白名单，无业务写入入口。
- 服务端定期采集，浏览器每 15 秒查询快照，手动刷新不会额外轮询 Odoo。
- 未配置、采集中、有效空数据、局部失败、连接失败和过期状态分别显示。
- 故障保留当前进程最后一份快照并淡化颜色；无自动演示回退。重启后重新采集。
- 非本机开放需配置口令；口令走请求头，不进入 URL。

已接入与小程序开发任务一致的 Odoo 测试账套，并完成四个入口的真实数据加载检查。2026-09-09 首轮读取库存明细 1,164 条、紧急采购订单 32 张；订单交付按最近 7 天更新范围为空。三个快照均为 live，尚需业务人员核对具体业务口径。

## 启动

运行 `启动灯塔.ps1`。首次会建立独立 Python 环境并安装锁定的依赖。

入口：http://127.0.0.1:8780/

独立副屏：

- `/boards/inventory/?screen=purchase`：采购异常
- `/boards/inventory/?screen=inventory`：库存通知
- `/boards/urgent/`：紧急采购
- `/boards/orders/`：订单交付
- `/?focus=1#orders`：专注模式打开订单交付

## 接入

将 `.env.example` 复制为 `.env`。复用 CRM 时，设置 `LIGHTHOUSE_CRM_ENV_FILE` 为 CRM 私有配置文件的实际路径，然后重启。只读取其中的 Odoo 配置，不修改 CRM 文件，也不调用 CRM 创建报价等写入功能。也可直接提供 CRM 原有变量 `ODOO_BASE_URL`、`ODOO_DATABASE`、`ODOO_USERNAME`、`ODOO_PASSWORD`。旧看板的 `ODOO_URL`、`ODOO_DB`、`ODOO_USER` 非空时优先使用。

2026-09-09 已从用户授权的小程序开发任务记录取得并验证最新连接：`http://192.168.1.100:8019`、`inspiri_erp_test`。公网 CRM 的旧健康字段及内网 8018 端口均不能代表该任务后来确定的统一 Odoo 连接。凭据仅保存在本机 `.env`，不写入本文档或前端。

默认仅本机可访问。开放局域网时必须设置 `LIGHTHOUSE_TOKEN`，经 HTTPS 反向代理访问。第一版口令是展示访问控制，尚不是按人、按部门或按公司的数据授权。

只启动一个应用进程；多 worker 会重复采集。如需横向扩容，再独立采集器与共享快照存储。

具体数据口径、已修复问题和上线前对账项见 [数据口径与迁入记录](docs/数据口径与迁入记录.md)。
