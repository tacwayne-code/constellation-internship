# Odoo 统一接口实施说明

## 已核验环境

- Odoo：18 Enterprise
- 业务 HTTP 端口：8019
- 实时消息端口：8072（不能作为业务 API 地址）
- 测试数据库：`inspiri_erp_test`
- 接口账号必须使用 Odoo 中的完整登录名；密码/API Key 仅保存于服务器 600 权限环境文件
- 2026-09-09 只读核验数量：客户 123、商品 2485、销售订单 106、采购订单 437、库存调拨 3009、生产订单 35、生产工单 144
- `maintenance.request` 不存在，说明当前未安装 Odoo Maintenance；ASS 工单不能直接依赖此模型

## 数据归属

| 数据 | 主数据系统 | CRM | ASS | 看板 |
|---|---|---|---|---|
| 客户、联系人 | 统一平台 + Odoo 编号 | 读写 | 读取 | 只读汇总 |
| 商品、单位、价格 | Odoo | 查询/选用 | 查询/选用 | 只读 |
| 销售订单 | Odoo | 创建草稿、查询状态 | 关联查询 | 销售/交付只读 |
| 售后工单、派单、维修记录 | 统一平台 | 关联查询 | 读写 | 售后统计 |
| 采购订单 | Odoo | 不直接操作 | 不直接操作 | 采购看板只读 |
| 库存调拨 | Odoo | 查询交付状态 | 查询备件状态 | 仓库看板只读 |
| 生产订单、生产工单 | Odoo | 查询交期 | 查询设备关联 | 生产大屏只读 |
| 身份、角色、审计 | 统一平台 | 使用 | 使用 | 使用 |

## 写入规则

1. CRM 新增客户时先生成稳定的 CRM 客户编号。
2. 统一平台记录幂等任务，再创建或匹配 Odoo `res.partner`。
3. 企业写为主客户，联系人写为该企业的子联系人。
4. Odoo 返回的 Partner ID 和 CRM 客户编号回写统一客户库和 CRM。
5. 网络或权限失败时保留客户记录并标记 `FAILED`，后台可重试；界面不能显示伪成功。
6. 小程序和浏览器不能传任意 Odoo 模型或方法，只能调用已定义业务接口。
7. 不开放删除、订单确认、冲销等高风险 Odoo 操作；这些操作继续在 Odoo 内完成。

## 上线闸门

1. 备份 Odoo 测试数据库和统一平台数据库。
2. `ODOO_WRITE_ENABLED=0` 启动，验证七类数据画像和客户预览。
3. 选择一个真实且允许录入的客户，在测试数据库执行一次写入闭环。
4. 核对主客户、子联系人、CRM 编号、Odoo Partner ID 与审计记录。
5. 开启 `ODOO_WRITE_ENABLED=1`，配置 CRM 内部桥；公网 Nginx 必须阻断 `/platform/api/internal/`。
6. 先让销售经理测试新增/修改客户，再逐步开放销售人员。

## 权限建议

当前接口账号在已安装的主要模型上拥有删除权限，超过应用实际需要。稳定运行后应在 Odoo 新建“企业接口”权限组：客户允许读/新增/修改，商品和采购/库存/生产允许只读，销售订单按业务需要允许创建与修改，所有模型取消删除权限。
