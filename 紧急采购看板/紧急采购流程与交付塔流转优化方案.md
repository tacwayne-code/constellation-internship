# 紧急采购流程与交付塔订单流转优化方案

> 编制日期：2026-08-17
> 适用范围：外购件采购（以 RGV 天地轨为例）与交付控制塔 #/sales 订单流转
> 关联系统：Odoo 18（inspiri_erp_test）+ 交付控制塔 V2（http://192.168.1.100:8000）

---

## 一、现状诊断：问题出在哪

### 1.1 采购现状（绕过 Odoo）

当前外购件采购是「**直接按清单线下采购**」：

```
项目立项 → 出外购件清单(Excel) → 采购员线下采购 → 货到车间
                                        ↑
                              全程不录入 Odoo，系统无任何记录
```

以 `RGV天地轨外购件清单.xlsx` 为例，经盘点：

| 项目 | 现状 |
| --- | --- |
| 物料行数 | 37 个外购件（天轨用 1-23、地轨用 24-38） |
| 物料编码 | **0 个填写**（清单只有名称，如「平垫圈16×3」） |
| 供应商 | **0 个填写** |
| 单价 / 金额 | **0 个填写** |
| 交货日期 | **0 个填写** |
| 数量 | 已填（如「48+3」= 48 台用量 + 3 备件） |

结论：这份清单是**纯 BOM 需求来源**，缺少采购执行所需的编码、供应商、价格、交期四要素，无法直接映射到 Odoo 产品与采购单。

### 1.2 造成的断层后果

1. **Odoo 无采购单**：线下采购不入账，`purchase.order` 里没有这些外购件的采购记录。
2. **交付塔看不到进度**：`#/sales` 里 RGV 天地轨项目的 `po_count = 0`，交付分析无法计算「已订 / 在途 / 缺口」。
3. **紧急采购无法自动发起**：交付塔的「紧急采购选项」依赖库存缺口和供应商数据，缺主数据时只能退回 Excel 线下买。
4. **数据不可追溯**：价格、到货、付款没有系统留痕，事后无法对账。

### 1.3 交付塔系统现状（已具备的能力）

实测盘点 `http://192.168.1.100:8000`（交付控制塔 V2，Odoo 18 + PLM 数据代理），**代码层已经具备完整的订单流转骨架**：

| 环节 | API | 状态 |
| --- | --- | --- |
| 销售单概览 | `GET /api/delivery-tower/sales` | ✅ 已就绪（含 `is_emergency` / `po_count` / `mo_count`） |
| 交付分析 | `GET /api/delivery-tower/orders/{so_id}/delivery-analysis` | ✅ 已就绪（需求-库存-在途=缺口） |
| 紧急采购选项 | `GET /api/delivery-tower/orders/{so_id}/urgent-purchase-options` | ⚠️ 返回 `suppliers: []`（缺供应商主数据） |
| 一键生成采购单 | `POST /api/delivery-tower/orders/{so_id}/create-urgent-purchases` | ⚠️ 缺 `partner_id` 参数时无法自动下单 |
| 采购概览 | `GET /api/delivery-tower/procurement/overview` | ✅ 已就绪（330 单 / 40 紧急 / 30 待处理 / 10 在途） |
| 紧急标记同步 | `POST /api/delivery-tower/sync/emergency` | ✅ 已就绪（已识别 S00123 / S00124） |

**实测关键现象**：

- 紧急单 `S00124`（编带机）的 `urgent-purchase-options` 返回 `{"product":"编带机","qty":13,"suppliers":[]}` —— 供应商为空。
- 交付分析对 S00124 展开 BOM 后，能正确算出「编带机缺口 13、定位结构/旋转结构/打带结构缺口 9」，但部分配件因缺供应商信息无法继续生成采购单。

**结论：断点不在代码，而在数据——产品没有维护「供应商」主数据（`product.supplierinfo`）。**

## 二、目标流程（调整后）

```
Odoo 建 SO（项目+客户）
   ↓
维护物料主数据 + BOM + 供应商
   ↓
交付塔自动算「外购件缺口」
   ↓
一键生成紧急 PO（自动带出供应商）
   ↓
供应商确认 → 收货入库
   ↓
交付塔 #/sales 实时可见进度
```

核心原则：**Excel 清单降级为「需求输入」，采购执行一律走 Odoo / 交付塔，实现线上闭环。**

## 三、调整动作（数据 → 流程 → 系统 三层）

### A. 数据补齐（最优先，前置条件）

这是所有流转跑通的前提，**先做数据，代码不用改**。

1. **建物料主数据**
   - 把 RGV 天地轨 37 个外购件逐个建成 Odoo 产品（`product.template` / `product.product`）。
   - 补齐**物料编码**（替代现在清单里只有中文名称、无编码的问题）。
   - 建议编码规则：`W-设备号-序号`（如 `W-DTJ-001`），与设备 `DTJ-300000` 关联。

2. **建供应商主数据**
   - 给每个产品挂 `product.supplierinfo`：供应商（`res.partner`）+ 单价 + 交期。
   - 这是解决 `suppliers: []` 的唯一途径，也是「一键采购」能自动带出 `partner_id` 的关键。

3. **建 BOM**
   - 把外购件挂到「RGV 天地轨」设备的 BOM（`mrp.bom`）上。
   - 交付分析正是靠 BOM 展开来计算缺口的，不建 BOM，缺口永远是 0。

4. **明确「外购件 vs 自制件」**
   - 清单里的「编带机」类整机是**成品/自制件**，不应被当成「需采购」。
   - 在 Odoo 里设置产品「采购 / 制造」路由（`route_ids`），交付塔据此区分「该买还是该生产」。

### B. 流程固化（采购规范）

1. **明确紧急采购标准流转**（建议写入制度）：
   - 需求来源：项目 BOM 展开 / 库存低于缺口 → 一律走 Odoo。
   - 执行：交付塔 `#/sales` → 选中紧急单 → 交付分析确认缺口 → 「一键生成紧急 PO」。
   - 线下 Excel 仅用于「设计阶段的初步估算」，不再作为采购执行凭证。

2. **紧急标记统一**：
   - 销售单打紧急标签（`crm.tag`）→ 用 `sync/emergency` 同步到关联 PO / MO。
   - 采购单 `priority=1`（Urgent）→ 交付塔 `procurement/overview` 自动归入「紧急待处理 / 在途」。

3. **职责切分**：
   - 采购员：负责建 PO、跟交期、录到货。
   - 技术/设计：负责维护 BOM 与物料主数据。
   - 项目负责人：在 `#/sales` 盯交付进度，红黄灯异常时发起紧急采购。

### C. 交付塔系统完善（代码层，按需迭代）

| 序号 | 完善项 | 说明 | 优先级 |
| --- | --- | --- | --- |
| 1 | 供应商自动匹配 | `urgent-purchase-options` 读 `supplierinfo` 填充 `suppliers`，支持缺省取默认供应商 | 高 |
| 2 | 成品 vs 外购件区分 | 按产品「采购/制造」路由，把「编带机」类自制件从「需采购」里排除，改提示「需生产」 | 高 |
| 3 | 反向传播按钮 | `PO→SO` 紧急状态反向同步的「立即同步」前端按钮（此前遗留未集成） | 中 |
| 4 | 采购选项接口加固 | `urgent-purchase-options` / `create-urgent-purchases` 加鉴权、错误信息脱敏 | 中 |
| 5 | RGV 项目录入 | 在 `project.project` 建「RGV 天地轨」项目，关联 SO / MO / PO，交付塔按项目聚合 | 中 |
