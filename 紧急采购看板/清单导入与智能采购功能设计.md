# 清单导入与智能采购功能设计

> 编制日期：2026-08-17
> 目标：把「Excel 外购件清单」直接导入系统，自动识别配件、推荐供应商、下单采购并回写记录
> 前置依赖：物料主数据 + 供应商主数据（product.supplierinfo）基本就绪

---

## 一、功能闭环（5 步）

```
① 导入清单 ──▶ ② 识别配件 ──▶ ③ 推荐供应商 ──▶ ④ 生成采购单 ──▶ ⑤ 采购回写
  上传 Excel        名称→产品         多源评分           一键建 PO         到货/价格入库
                                              ▲                              │
                                              └────────── 回写 supplierinfo ──┘
```

核心价值：**采购成功一次，主数据就自动变完整一次**，下次识别更准、推荐更准，形成自我增强的闭环。

---

## 二、现状盘点（数据原料）

| 数据 | 数量 | 可用字段 | 用途 |
| --- | --- | --- | --- |
| 产品主数据 | 2476 | 产品编码 / 名称 / 分类 / 类型 | ② 识别目标 |
| 供应商主数据 | 150 | 名称 / 等级(1/2) / 状态 | ③ 推荐候选 |
| 采购单 | 345 | 供应商 / 下单日期 / 金额 / 状态 | ③ 历史采购频次 |
| BOM | 36 | 产品 / 子件项数 | 需求展开依据 |
| supplierinfo | 缺 | — | ③ 首选来源（待补） |

关键缺口：产品未挂 `product.supplierinfo`，导致当前「一键采购」拿不到供应商。推荐算法需同时支持「supplierinfo 命中 / 历史采购推断 / 人工指定」三档。

## 三、物料识别设计（清单 → 产品）

### 3.1 匹配流程（按优先级）

| 优先级 | 匹配方式 | 说明 |
| --- | --- | --- |
| 1 | 编码精确匹配 | 清单「编号」= 产品编码，直接锁定 |
| 2 | 名称规范化后精确匹配 | 全角→半角、`×`→`x`、`．`→`.`、`㎡`→`m2`、去空格 |
| 3 | 核心词 + 规格匹配 | 提取「标准件类型词」+「规格型号」双维度比对 |
| 4 | 模糊匹配 + 评分 | 编辑距离 / 关键词包含度，给出匹配度分数 |

### 3.2 名称规范化规则（针对标准件清单）

以 `RGV天地轨外购件清单.xlsx` 实际数据为例：

| 清单原文 | 规范化后 | 核心词 | 规格 |
| --- | --- | --- | --- |
| 平垫圈16×3 | 平垫圈16x3 | 平垫圈 | 16x3 |
| 六角螺母M16 | 六角螺母M16 | 六角螺母 | M16 |
| M12X100化学螺栓 | M12x100化学螺栓 | 化学螺栓 | M12x100 |
| 内六角圆柱头螺钉M8×20 | 内六角圆柱头螺钉M8x20 | 内六角圆柱头螺钉 | M8x20 |
| 四集6㎡滑触线长14248mm | 四集6m2滑触线长14248mm | 滑触线 | 6m2/14248mm |

> 建议维护一张「标准件类型词库」（平垫圈 / 弹性垫圈 / 六角螺母 / 内六角螺钉 / 化学螺栓 / 滑触线…），匹配时先按词库切词，再比对规格，准确率最高。

### 3.3 匹配度分级与处理

| 分数 | 分级 | 系统行为 |
| --- | --- | --- |
| ≥ 90 | 高置信 | 自动关联产品，无需人工 |
| 60–89 | 中置信 | 列出 Top 3 候选产品，人工点选确认 |
| < 60 | 低置信 / 无匹配 | 标记「待新建产品」，提示创建产品 + 编码 |

## 四、供应商推荐设计

### 4.1 数据源优先级

1. **supplierinfo 命中**（首选）：产品已维护供应商 → 直接带出，含价格、交期。
2. **历史采购推断**（次选）：统计 `purchase.order.line` 里该产品 → 对应 `partner_id` 的采购频次与最近时间。
3. **供应商等级**：`vendors` 的等级字段（1 级优先于 2 级）。
4. **人工指定**（兜底）：无历史则采购员手工选，选完即回写 supplierinfo。

### 4.2 推荐评分公式（建议）

```
score = 0.40 × 采购频次得分 + 0.25 × 最近采购时间衰减 + 0.20 × 供应商等级 + 0.15 × 价格优势
```

- 采购频次得分：`min(次数, 10) / 10`。
- 最近性衰减：最近一次采购距今越近分越高（如 30 天内=1.0，逐年衰减）。
- 供应商等级：1 级 = 1.0，2 级 = 0.6。
- 价格优势：同产品历史最低价供应商得高分。

### 4.3 输出

每个识别成功的物料，返回 `推荐供应商 Top 1`（默认）+ `候选列表 Top 3`，采购员一键确认或切换。

## 五、采购执行与回写

### 5.1 生成采购单

- 复用交付塔已有能力：`POST /api/delivery-tower/orders/{so_id}/create-urgent-purchases`，`vendors = {product_id: partner_id}` 自动带入推荐供应商。
- 若无销售单来源（纯外购件清单），新增「按清单批量建 PO」接口：一条清单 → 按供应商聚合成多张 PO（同一供应商合并一张）。

### 5.2 采购成功后的回写（关键闭环）

| 回写项 | 写入位置 | 作用 |
| --- | --- | --- |
| 供应商 | `product.supplierinfo.partner_id` | 下次自动带出供应商 |
| 单价 | `product.supplierinfo.price` | 下次带出价格，支撑价格对比 |
| 交期 | `product.supplierinfo.delay` | 支撑交付分析算 ETA |
| 到货 | Odoo 收货单（stock.picking） | 交付塔 #/sales 进度更新 |

> 这一步是「自我增强」的核心：只要采购成功一次，主数据就自动补一条，之后该物料再出现即走自动推荐，无需人工。

## 六、API 设计（新增，交付塔后端）

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/procurement/import` | POST | 上传 Excel/CSV，返回解析结果（名称/数量/规格） |
| `/api/procurement/match` | POST | 输入解析行，返回产品匹配（product_id + 匹配分 + 候选） |
| `/api/procurement/recommend` | POST | 输入 product_id 列表，返回推荐供应商 Top3 |
| `/api/procurement/batch-create-po` | POST | 按「供应商聚合」批量建 PO，返回 PO 单号 |
| `/api/procurement/import-preview` | POST | 导入前预览：识别+推荐结果，人工确认后落库 |

> 现有 `products / vendors / procurement` 模块的 `rows` 接口已提供产品、供应商、采购单数据，可作为匹配与推荐的取数基础，无需改动 Odoo 侧。

## 七、落地建议

| 阶段 | 动作 | 验收 |
| --- | --- | --- |
| 1. 数据 | 补齐 supplierinfo（至少覆盖常用标准件） | 常用件能带出供应商 |
| 2. 识别 | 先做「编码 + 名称规范化」匹配，配标准件词库 | 清单导入命中率 > 80% |
| 3. 推荐 | 历史采购推断 + 等级评分，缺省人工兜底 | 推荐 Top1 可一键下单 |
| 4. 回写 | 采购成功自动写 supplierinfo | 第二次同物料自动带出 |

> 建议先拿 `RGV天地轨外购件清单.xlsx` 这 37 个标准件做试点：补主数据 → 跑通导入识别 → 验证推荐 → 走一遍采购回写，再推广到全部外购件。

## 八、与紧急采购看板的衔接

紧急采购看板（只读）读的是 Odoo `purchase.order` 中标「紧急」且未采购的单据，与智能采购**同一数据源，天然打通**：只要第 ④ 步把 PO 正确落进 Odoo，看板自动上墙，无需改看板代码。

### 8.1 各阶段 → 看板显示映射

| 智能采购阶段 | Odoo 数据状态 | 看板显示 |
| --- | --- | --- |
| ① 导入 / ② 识别 / ③ 推荐（尚未下单） | 无 PO（数据在交付塔导入层） | 不显示 |
| ④ 生成采购单 | `draft` + `priority=1` + `date_planned` | **显示，按交期分 P0~P3** |
| 确认下单 | `sent` | 显示「已发送」 |
| 确认转采购 | `purchase` | 移出「未采购」范围 |
| ⑤ 采购完成回写 | `done` | 移出看板，交付塔显示「已到货」 |

### 8.2 衔接三要素（生成 PO 时必填）

| 字段 | 作用 | 缺失后果 |
| --- | --- | --- |
| `priority=1` | 看板据此识别「紧急」 | 不进看板，被当成普通单 |
| `date_planned` | 看板据此分 P0~P3 | 落到「未设置预计日期」，无法分级 |
| `partner_id` | 带出推荐供应商 | 「供应商」列与排行显示为「未指定」 |

### 8.3 可选增强（要看更丰富数据时）

- PO 增加自定义字段标记「来源 = 清单导入」，看板色块/明细加「来源」徽标，区分「清单导入」与「手工建单」。
- 若希望看板也能看到「导入后尚未下单」的物料，需给看板新增数据源：读交付塔导入暂存结果，或在 Odoo 新增「采购需求」中间模型。
